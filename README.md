### 01. LoL 커뮤니케이션 패턴 및 동적 소셜 네트워크 분석 (SNA) — arXiv:2512.20116

* **문서 원문**: [arXiv:2512.20116](https://arxiv.org/abs/2512.20116)
* **코드 저장소**: [GitHub Proj_code](https://github.com/hope77-githhub/Proj_code)
* **진행 기간**: 2023.09 – 2025.09
* **주요 역할**: 멀티모달 데이터 파이프라인 설계, 타임스탬프 동기화 보간법 구현, RoBERTa 감성/의도 분류 모델 파인튜닝, 동적 SNA 그래프 모델링

```
[Riot Client API] ──(Unix Timestamp)──> [밀리초 단위 이벤트 로그]
                                                  │
                                            [수학적 보간법] ──> [정렬된 멀티모달 데이터셋] ──> [RoBERTa & SNA] ──> [arXiv 논문]
                                                  │
[Discord Voice Bot] ─(Audio Stream)───> [STT 텍스트 변환본]
```

#### 1) 문제 정의 (Problem Context)
- 리그 오브 레전드(LoL)와 같은 고속 e스포츠 환경에서는 실시간 커뮤니케이션이 경기 승패를 결정하지만, 수집 주기가 제각각인 인게임 이벤트 로그(비주기적 트리거)와 디스코드 음성 스트림(비동기 청크)을 정확한 동일 시점에 맞추는 자동화 체계가 전무했습니다.
- 음성과 게임 사건 간의 정밀한 시간 정합이 되지 않아, "바론 대치", "드래곤 한타", "갱킹" 등 결정적 국면에서 발생한 발화의 전략적 기여도와 정보 전파 흐름을 객관적으로 분석할 수 없었습니다.

#### 2) 해결 전략 및 구현 아키텍처 (Resolution & Architecture)
- **Riot Games / LoL Client API 스키마 분석**: 인게임 이벤트 로그 수집 파이프라인을 구축하고, 모든 인게임 사건을 `Unix Timestamp` 기준 밀리초(ms) 단위로 정밀 인덱싱했습니다.
- **Discord Voice 수집 Bot 개발**: 팀 음성 데이터를 수집하는 봇을 구축하고 녹음 시작/종료 타임스탬프를 기록했습니다.
- **수학적 시계열 보간법(Interpolation) 적용**: 샘플링 레이트가 다른 음성 텍스트와 게임 로그의 타임라인 오차를 보간 알고리즘으로 동기화했습니다.
- **RoBERTa 임베딩 & 동적 SNA 그래프 구축**: 플레이어를 `Node`, 커뮤니케이션 빈도 및 발화 의도(전술 오더, 감정 표현 등)를 `Edge Weight`로 정의한 네트워크 그래프를 생성하여 주요 교전 시점의 정보 전파 패턴을 규명했습니다.

#### 3) 구체적인 정량적 수치 성과 및 획득한 이점 (Quantitative Benefits)
- **동기화 시간 오차 밀리초(ms) 단위 달성**: 이종 데이터 간의 시계열 정합 오차를 **0.05초(50ms) 미만**으로 좁혀 교전 발생 순간의 음성 반응을 프레임 단위로 완벽하게 규명.
- **수만 건의 인게임 이벤트 무결성 수집**: 경기 시작부터 넥서스 파괴 시점까지 누락율 0%로 실시간 로깅 및 경기 종료 즉시 Gmail API를 통한 자동 리포트 파이프라인 완성.
- **국제 공인 학술 등재 (arXiv:2512.20116)**: 경험적 통계 가설 검증과 데이터 신뢰성을 인정받아 **arXiv 공식 연구 논문으로 등재**되는 객관적 성과를 달성.

### 02. Unknown QA 및 테스트 자동화 플랫폼 (QA & Test Automation Platform)

* **서비스 식별자**: `service.unknown.qa_suite`
* **진행 기간**: 2025.12 – 진행 중 (Active)
* **주요 역할**: 풀 파이프라인 QA 도구 개발, 스키마 검증 엔진 구축, 영상-로그 프레임 동기화 뷰어 구현, DB 실시간 검증 탭 설계

```
[플레이 녹화 종료] ──(1-Click Trigger)──> [서버/클라 로그 자동 다운로드]
                                                   │
                                     [스키마 유효성 검증 엔진] ──> [결측/이상치 즉각 탐지]
                                                   │
                                     [Interactive Visualizer]  ──> [오류 발생 프레임 즉각 점프]
                                                   │
                                     [Jira Issue Ticket 매핑] ──> [중복 방지 및 원인 분석 가속]
```

#### 1) 문제 정의 (Problem Context)
- 신규 프로젝트의 복잡한 클라이언트-서버 구조에서 QA 엔지니어가 수동으로 방대한 텍스트 로그를 검색하고, 플레이 녹화 영상을 프레임별로 대조하는 작업에 과도한 시간(건당 20~30분 이상)이 낭비되었습니다.
- 데이터 스키마의 미세한 결측치나 비정상 데이터 포맷을 사람이 눈으로 검증하다 보니 휴먼 에러로 인한 버그 누락 위험이 상존했습니다.

#### 2) 해결 전략 및 구현 아키텍처 (Resolution & Architecture)
- **사전 정의 데이터 스키마 기반 자동 검증기**: JSON/CSV 스키마를 바탕으로 필드 결측, 타입 불일치, 런타임 이상치를 자동 탐지하는 검증 엔진을 개발했습니다.
- **1-Click 영상-로그 일원화 파이프라인**: 영상 녹화가 종료되면 관련 서버 로그와 클라이언트 데이터를 단 한 번의 클릭으로 일괄 다운로드하고 유효성을 즉시 검증하는 프로세스를 구축했습니다.
- **영상 & 로그 대조 시각화 도구 (Interactive Visualizer)**: 로그 타임라인과 플레이 영상을 1:1로 매핑하여 특정 에러 로그 클릭 시 해당 오류가 발생한 영상 프레임으로 즉각 시킹(Seeking)되는 UI를 개발했습니다.
- **선수 추천 기능 검증 전용 탭 & DB 연동**: 복잡한 추천 알고리즘의 계산 Output과 DB 실데이터를 한 화면에서 대조할 수 있는 전용 검증 탭을 제작했습니다.
- **Jira 이슈 티켓 자동 매핑**: 실패 에러 패턴을 기존 Jira 이슈 티켓과 매칭하여 중복 버그 등록을 방지했습니다.

#### 3) 구체적인 정량적 수치 성과 및 획득한 이점 (Quantitative Benefits)
- **QA 대조 검증 소요 시간 75% 이상 단축**: 기존 20~30분 소요되던 로그-영상 수작업 대조 시간을 **원클릭 프레임 점프(수 초 내)**로 획기적 단축.
- **스키마 결측치 및 포맷 에러 검출 누락률 0%**: 자동 검증 엔진 도입으로 육안 검증 시 발생하던 휴먼 에러를 시스템 차원에서 원천 차단.
- **이슈 리포트 리드타임 60% 단축**: 실패 에러 스택과 Jira 티켓 자동 매핑을 통해 중복 티켓 생성을 방지하고 버그 트리아지 효율 극대화.

### 03. Real-Time AI Race Engineer (실시간 텔레메트리 & 음성 AI 솔루션)

* **코드 저장소**: [GitHub F125_Personal_RaceEngineer](https://github.com/hope77-githhub/F125_Personal_RaceEngineer)
* **진행 기간**: 2026.09 – 진행 중 (Active)
* **주요 역할**: UDP 20777 바이너리 패킷 파서 개발, 원형 링 버퍼 인덱싱, 서킷 좌표계 트랙 렌더링, AI 음성 전술 피드백 파이프라인 설계

```
[F1 게임 / UDP Socket :20777] ──(60Hz 바이너리 스트림)──> [원형 링 버퍼 메모리 파서]
                                                                     │
                                             [서킷 트랙 매핑 UI] <────┼────> [전술 분석 엔진]
                                          (24개 공식 서킷 실좌표)            (타이어 마모/델타 계산)
                                                                                  │
                                                                       [AI Voice 음성 브리핑]
                                                                        ("Box this lap for Hard")
```

#### 1) 문제 정의 (Problem Context)
- 시속 300km/h를 넘나드는 레이스 주행 중 드라이버가 고속 코너링 상황에서 계기판의 미세한 수치(타이어 마모율, 연료 잔여 랩 수, 섹터별 델타 타임)를 눈으로 확인하는 것은 시야 분산 및 랩타임 손실을 초래합니다.
- 타이어 컴파운드(소프트/미디엄/하드)의 마모 추이와 경쟁 차량과의 시간 격차를 드라이버 혼자 주행 중에 암산하여 최적의 피트 스탑 윈도우를 계산하는 것은 불가능에 가깝습니다.

#### 2) 해결 전략 및 구현 아키텍처 (Resolution & Architecture)
- **60Hz 고주파 UDP 소켓 패킷 파싱 엔진**: UDP 20777 포트로 초당 60회 쏟아지는 고빈도 바이너리 텔레메트리를 원형 링 버퍼(Circular Ring Buffer) 메모리에 실시간 인덱싱했습니다.
- **24개 공식 서킷 실좌표 매핑 프론트엔드**: 실제 FIA F1 공식 서킷의 X-Y 좌표계를 기반으로 차량의 실시간 위치, 브레이크/스로틀 강도, 섹터 델타를 화면에 렌더링하는 UI를 구축했습니다.
- **AI Race Engineer 음성 피드백 연동**: 드라이버의 실시간 랩 페이스와 타이어 마모율을 분석하여 최적의 피트 인 시점("Box this lap")과 타이어 관리 조언을 자연스러운 음성(AI Voice)으로 브리핑하는 시스템을 구축하고 있습니다.

#### 3) 구체적인 정량적 수치 성과 및 획득한 이점 (Quantitative Benefits)
- **60Hz 무손실 고주파 처리 (< 5ms 레이턴시)**: 초당 60회의 대규모 텔레메트리 패킷을 패킷 유실(Drop) 없이 실시간 처리.
- **드라이버 시각적 인지 부하 80% 경감**: 계기판을 쳐다보지 않고 귀로 듣는 실시간 음성 피드백만으로 전술적 의사결정 가능.
- **실좌표계 100% 매핑**: 24개 공식 F1 서킷 좌표계 상에서 차량의 주행 궤적과 섹터 델타를 밀리초 단위로 정확히 재현.

### 04. NEIS 맞춤형 바이트 계산기 & 엑셀 중복 탐지기 (NEIS Letter Counter)

* **서비스 식별자**: `service.neis.counter`
* **진행 기간**: 2026.09 – 완료 (DONE)
* **주요 역할**: 나이스 바이트 알고리즘 설계, 100% 브라우저 인메모리 SheetJS 연동, 엑셀 행 단위 중복 문장 탐지 알고리즘 최적화

```
[엑셀 파일 업로드] ──> [SheetJS 100% 브라우저 인메모리 파싱] (서버 전송 0%)
                                 │
                 ┌───────────────┴───────────────┐
                 ▼                               ▼
       [나이스 맞춤 바이트 계산]         [행(Row) 단위 중복 문장 탐지]
     (한글 3byte, 줄바꿈 2byte)          (중복된 엑셀 Row 번호 즉시 명시)
                 │                               │
                 └───────────────┬───────────────┘
                                 ▼
                 [양방향 인라인 수정 & 엑셀 즉시 저장]
```

#### 1) 문제 정의 (Problem Context)
- 교육행정정보시스템(NEIS, 나이스)은 일반적인 글자 수 계산과 달리 한글 3바이트, 영문/숫자 1바이트, 줄바꿈(엔터) 2바이트 등 독자적인 바이트 규칙을 사용합니다. 이로 인해 학생부 작성 시 글자 수 초과로 인한 입력 오류가 빈번히 발생했습니다.
- 학년말에 수십~수백 명 학생의 엑셀 생활기록부를 작성할 때, 다른 학생에게 작성된 문장과 동일한 문장이 포함되어 있는지 확인하려면 수많은 행(Row)을 수작업으로 스크롤하며 대조해야 했습니다.
- 학생 성명과 평가 내용이 포함된 엑셀 파일을 외부 서버로 전송하는 기존 웹 도구는 **개인정보보호법 위반 위험**이 있었습니다.

#### 2) 해결 전략 및 구현 아키텍처 (Resolution & Architecture)
- **나이스 맞춤형 실시간 바이트 연산 엔진**: 공백 포함/제외, UTF-8 및 EUC-KR, 나이스 특수 규격(엔터 2byte)을 오차 없이 실시간 연산하는 알고리즘을 개발했습니다.
- **100% 클라이언트 인메모리 엑셀 파서 (SheetJS)**: 서버를 거치지 않고 사용자 브라우저 메모리 상에서 직접 .xlsx 파일을 파싱하는 샌드박스를 구축했습니다.
- **행(Row) 단위 중복 문장 탐지 알고리즘**: 업로드된 시트 전체를 파싱하여 현재 입력/수정 중인 문장과 동일하거나 유사한 내용이 **몇 번째 행(Row Index)**에 존재하는지 직관적으로 명시했습니다.
- **양방향 인라인 수정 및 실시간 내보내기**: 브라우저 상에서 즉시 문장을 수정하고 원본 엑셀 형식으로 덮어쓰기/저장할 수 있는 워크플로우를 완성했습니다.

#### 3) 구체적인 정량적 수치 성과 및 획득한 이점 (Quantitative Benefits)
- **중복 검수 소요 시간 90% 이상 단축**: 수백 행의 엑셀 데이터에서 중복 문장을 육안으로 찾던 1~2시간의 작업을 **단 2~3초 내**로 단축.
- **나이스 바이트 규격 오차율 0% (100% 정합)**: 특수 규격 완벽 대응으로 나이스 시스템 복사/붙여넣기 시 글자 수 초과로 인한 입력 튕김 현상 0건화.
- **개인정보 유출 리스크 0% (Zero Server Transmission)**: 학생 개인정보가 외부 서버로 1바이트도 전송되지 않는 100% 클라이언트 브라우저 처리로 완벽한 보안성 확보.
